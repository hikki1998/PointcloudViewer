## 工程级 CRS 模块化与对话框设计方案

### Summary
- 将 CRS 相关能力拆成独立 DLL，模块职责覆盖：常见坐标系目录、工程级 CRS 数据模型、查询/筛选、坐标转换、最近使用记录、以及通用 CRS 选择对话框。
- 主程序保留“工程属性”入口；工程属性页只负责展示和调用，不再持有 CRS 业务逻辑。用户流为：
  - 打开“工程属性”
  - 分别查看 `点云坐标系` 与 `地理坐标系`
  - 点击“选择”按钮弹出通用 CRS 选择器
- 首版不支持自定义坐标系；坐标系目录采用“`中国+全球常用`”的内置 curated catalog。
- 视觉风格不照搬参考图的传统样式，改为“结构参考图、视觉沿用现有项目浅色圆角对话框体系”。

### Implementation Changes
- 新增独立 DLL，例如 `LASViewerCrs`。
  - 对外暴露 Qt/C++ API，而不是 C API 或 COM。
  - DLL 内部包含：
    - `CoordinateSystemRef`
    - `ProjectCoordinateSystems`
    - `CrsCatalogEntry`
    - `CrsCatalogService`
    - `CrsTransformService`
    - `RecentCrsStore`
    - `CrsSelectionDialog`
    - `ProjectCoordinateSystemsDialog`
  - 主程序只依赖 DLL 头文件和导出类；现有 `MainWindow` 只保留入口动作、结果回填、工程保存加载接线。
- DLL 的数据边界固定为：
  - `pointCloudCrs`：工程内部工作坐标系，要求是投影坐标系；未设置时允许为空。
  - `geographicCrs`：地理坐标系；首版默认并锁定为 `EPSG:4326 / WGS 84`，只允许从常见地理 CRS 中替换，不允许留空。
  - `CoordinateSystemRef` 至少包含：`authName`、`code`、`displayName`、`wkt`、`kind(projected/geographic)`、`deprecated`。
- 选择器对话框设计固定为两层：
  - `ProjectCoordinateSystemsDialog`
    - 两个分组：`点云坐标系`、`地理坐标系`
    - 每组显示：当前名称、`EPSG` 码、类型、简短描述
    - 每组提供：`选择...`、`清除`（仅点云 CRS）、`恢复 WGS84`（仅地理 CRS）
    - 底部 `确定/取消`
  - `CrsSelectionDialog`
    - 顶部：过滤框 + 类型切换
    - 中部上半：最近使用过的坐标系
    - 中部下半：世界坐标系树/分组列表
    - 底部：当前选择摘要 + WKT/PROJ 文本预览
    - 底部按钮：`确定/取消`
- 选择器布局与行为固定如下：
  - 结构参考你给的图：过滤、最近使用、世界坐标系、已选摘要、详情预览。
  - 视觉使用当前项目对话框体系：浅色背景、圆角卡片、统一按钮和表头样式。
  - 不提供“用户自定义坐标系”节点。
  - “添加坐标系”按钮改成只读的“类型筛选/快速分类”控件，不做新增动作，避免误导。
  - 双击列表项等于确认。
  - 过滤支持名称、`EPSG:xxxx`、别名关键字。
  - 最近使用最多保留 8 个，按最近确认顺序排序。
- 坐标系目录首版范围固定为：
  - 全球基础：`EPSG:4326`、`EPSG:3857`
  - 全球常用投影：常见 UTM 分区
  - 中国常用地理：`EPSG:4490`、`EPSG:4326`
  - 中国常用投影：CGCS2000 3 度/6 度高斯分带常用中央经线，外加北京54、西安80 的常用带号
  - 不做“全 EPSG 数据库浏览”；仅内置 curated 列表
  - 目录分组固定为：`地理坐标系统`、`投影坐标系统`
- 工程文件与兼容策略：
  - CRS 的唯一持久化入口改为 `projectProperties.coordinateSystems`
  - 继续兼容旧 `routePlanning.crs` 读取，但新版本不再把它作为主数据源
  - 旧工程加载时：
    - 若存在新字段，用新字段
    - 否则用旧 `sourceEpsg` 迁移到 `pointCloudCrs`
    - `geographicCrs` 缺省填 `EPSG:4326`
- 转换能力边界：
  - 坐标转换实现放进 DLL，由 `PROJ` 驱动
  - GDAL 暂不进入首版链接链路；仅作为后续 GIS 能力扩展预留
  - DLL 对外提供：按 `CoordinateSystemRef` 或 `EPSG` 转换点/路线的同步接口
- CMake 组织方式：
  - 新增 `src/crs/` 或 `modules/crs/` 目录承载 DLL 源码
  - 顶层 CMake 增加 `add_library(... SHARED ...)`
  - 主程序链接该 DLL
  - `PROJ` 探测与链接从主程序迁到 CRS DLL
  - 对话框翻译字符串也归 DLL 的 Qt 翻译源统一管理

### Public Interfaces
- `CoordinateSystemRef`
  - 稳定字段：`authName`、`code`、`displayName`、`wkt`、`kind`、`deprecated`
- `ProjectCoordinateSystems`
  - 稳定字段：`pointCloudCrs`、`geographicCrs`
- `CrsCatalogService`
  - `allEntries()`
  - `filter(query, kind)`
  - `recentEntries()`
  - `findByCode(authName, code)`
- `CrsTransformService`
  - `canTransform(source, target)`
  - `transformPoint(...)`
  - `transformPolyline(...)`
- `ProjectCoordinateSystemsDialog`
  - 输入：当前 `ProjectCoordinateSystems`
  - 输出：确认后的 `ProjectCoordinateSystems`
- `CrsSelectionDialog`
  - 输入：允许的 CRS 类型、当前值、最近使用集合
  - 输出：选中的 `CoordinateSystemRef`

### Test Plan
- 目录与选择器
  - 过滤 `32651`、`WGS 84`、`CGCS2000` 能命中正确条目
  - 类型切换只显示对应 `projected/geographic` 项
  - 最近使用列表在多次确认后顺序正确
  - 废弃坐标系默认不显示
- 工程属性流
  - 工程属性页能分别设置点云 CRS 和地理 CRS
  - 点云 CRS 允许清空，地理 CRS 默认并保留 `EPSG:4326`
  - 从工程属性页进入选择器后，确认/取消行为正确
- 兼容与持久化
  - 打开旧工程时能从 `routePlanning.crs.sourceEpsg` 正确迁移
  - 保存新工程后只以 `projectProperties.coordinateSystems` 为主
  - 新工程再次打开后 CRS 不丢失
- 转换与业务接线
  - 航线导入导出改用工程级 CRS 后结果与旧逻辑一致
  - `PROJ` 缺失时，选择器仍可用，但转换相关入口给出明确提示
- UI 风格
  - 对话框在中英文下布局不破
  - 表头、按钮、选中态、详情预览与当前项目风格一致

### Assumptions
- 首版不支持自定义 CRS，也不提供“导入 WKT/PROJ 字符串”入口。
- CRS DLL 可以包含 QWidget/Qt Model，不追求跨非 Qt 宿主复用。
- 首版优先做 curated catalog，不接完整 EPSG 浏览器。
- `geographicCrs` 默认值为 `EPSG:4326 / WGS 84`。
- CRS 详情预览默认显示 WKT；若无 WKT，则回退显示 `EPSG` 和简要说明。
